## 既知の問題

### ERC20許可の競合状態

**ステータス:** 文書化済み（仕様上の制限）

ERC20標準には、許可量変更時の競合状態の問題があります。これは標準の制限であり、修正するとERC20互換性が失われます。

**緩和策:**
- `increaseAllowance`/`decreaseAllowance`の使用
- 許可変更前のゼロ設定

## 派生コントラクトの監査チェックリスト

ERC20を継承したコントラクトを監査する際のチェックリスト：

### 基本チェック

- [ ] コンストラクタが適切に親コンストラクタを呼び出している
- [ ] `_mint`関数が適切に制限されている
- [ ] `_burn`関数が適切に制限されている

### カスタマイズチェック

- [ ] `_update`のオーバーライドが正しく実装されている
- [ ] `decimals`のオーバーライドが一貫している
- [ ] カスタムエラーが適切に定義されている

### 統合チェック

- [ ] 他のコントラクトとの統合が安全
- [ ] リエントランシー攻撃への対策
- [ ] フロントランニング攻撃への対策

## バグバウンティ

OpenZeppelin Contractsはバグバウンティプログラムを実施しています。

- **プログラム:** Immunefi
- **報奨金:** 重大度に応じて最大 $100,000

### 報告方法

1. Immunefiプラットフォームから報告
2. 公開前に修正の機会を提供
3. 責任ある開示ポリシーに従う
